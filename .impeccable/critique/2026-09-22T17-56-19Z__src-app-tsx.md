## Priority Issues

[P1] The new orange accent fails contrast with white text/icons — a real regression from today
White on color.accent (#ff8a3d) computes to ~2.3:1 — below even the 3:1 minimum for UI components. Hits every PrimaryButton, the Fab, RoutineTab's "Entrenar"/"Semanas · N" pills, and the active tab circle. The prior coral was already marginal (~3.6:1); the new orange made it worse.
Fix: a distinct darker accentText/accentDeep token for anything carrying white text, or switch primary button/Fab text to near-black against the current orange.
Suggested command: /impeccable harden or /impeccable colorize

[P1] The Fab overlaps the bottom of scrolled content — clearance math never accounted for the Fab's own height
App.tsx/Fab.tsx's clearance comments derive spacing only from the tab bar's footprint, never from the Fab's own rendered height (~48-50px). Scrolled to the bottom of a list, the Fab's top edge can overlap the last visible card.
Fix: derive content paddingBottom (or the Fab's bottom offset) from Fab height + offset + margin explicitly, not just the tab bar's geometry.
Suggested command: /impeccable harden

[P2] Bottom-nav inactive icons contradict the contrast rule documented today
App.tsx uses color.textTertiary for inactive tab icons; Button.tsx explicitly says icon-only controls must use textSecondary "since icon-only controls have no text fallback for contrast."
Fix: swap inactive tab icon color to color.textSecondary.
Suggested command: /impeccable harden

[P2] Modal has no dialog semantics, no Escape-to-close, no focus trap/return
No role="dialog"/aria-modal, no keydown handler for Escape anywhere in the codebase, no focus trap or return-to-trigger on close.
Fix: add role="dialog" + aria-modal="true" + a labeled heading, an Escape handler, and focus return.
Suggested command: /impeccable harden

[P2] Incomplete ring rollout: NutritionTab shows the same kcal metric two different ways in one tab
The day-detail card uses RingProgress; the home list's day cards still render the old linear bar for the identical totals.kcal/maxKcal ratio.
Fix: either bring the home list onto RingProgress too, or document the split as an intentional at-a-glance/in-detail tradeoff.
Suggested command: /impeccable polish
